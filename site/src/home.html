TARAworkbench
Get started Documentation GitHub

From what is worth protecting to what you did about it.

TARA workbench is an open-source tool for the threat analysis and risk assessment of a product with digital elements. It follows the method of ISO/SAE 21434 and covers the essential requirements of the EU Cyber Resilience Act, from the first description of the product to a signed report. It runs on your own machine, and your data stays there.

Get started Read an example

A TARA answers four questions. The tool is laid out along them.

  1. What are we assessing?

    The scope, the item, and its architecture, drawn as a data flow diagram: components, outside parties, data stores, the flows between them, and the trust boundaries they cross.

    Lay an attack path over the drawing to follow it step by step, or lay the gaps over it to see where a risk lands that no control meets.

  2. What could go wrong, and how bad would it be?

    Assets, the damage when one is compromised, and the threats that bring it about. Each damage scenario is rated for safety, money, operation and privacy; the highest of the four is its impact.

    Every record shows one status: the next thing it needs. You never have to guess what is missing.

  3. How easy is it, and so how big is the risk?

    An attack path is rated on five factors: time, expertise, knowledge of the product, opportunity and equipment. The points add up to a feasibility, and impact and feasibility give a risk value from 1 to 5.

    The value is never typed in. Change an input and everything that rests on it follows, including the reviews that covered the old value.

  4. What do we do about it, and how do we know it works?

    Controls, a decision on each risk, the goal or the claim behind it, and the evidence. A control counts only once it is in the product and a test has shown that it works.

    Then one decision for each of the 21 essential requirements of CRA Annex I, with what the assessment says about it beside it.

A review that notices when its subject changes

When you record a review, the tool takes everything that review covered, the record and every input its result rests on, and keeps a fingerprint of it.

Change a damage rating, and the review of every risk that rests on it says so and asks to be confirmed again. Nothing that was reviewed can change quietly, and a released assessment cannot change at all.

How reviews work

Every change kept, and any of them undone

Each change is recorded with who made it and what it changed, from what to what. Several people can work in the same assessment; if two change the same field, the second is told instead of overwriting the first.

How the history works

Your assessment is a file you can read

There is no database. A TARA is one JSON document in a folder, with the history of its changes beside it. The ID you see on screen is the ID in the file.

  • To back up, copy the folder.
  • To keep an assessment beside the product's code, commit the file.
  • To read it in ten years, open it with anything.

The tool sends nothing anywhere: no telemetry, no fonts from a network, no update check.

The report is there from the first entry

One self-contained web page, laid out for A4: summary, scope, the architecture drawn, every table from assets to evidence, the risk matrix, the decisions on the CRA requirements, and what is still open.

It is made from the same results the screens show, so it cannot disagree with them. Until three people have signed, it says "draft" on every page.

Three assessments to learn from

Invented products, the real method. Every record is filled in and every check is settled, so you can change something and watch what reacts.

  1. A kettle you can switch on from your phone

    How a risk value comes about. Five risks that land on the five values, each for a different reason. Fifteen minutes, no background needed.

  2. A smart door lock

    What the assessment of an ordinary connected product looks like. The easiest attack needs no access to the lock at all.

  3. A remote service gateway for a machine

    A product in someone else's plant: two trust boundaries, a risk to people, a risk that is shared, and controls that are procedures.

Run it

With Docker

git clone {{repository}}.git
cd cratool-tara-oss
mkdir data
docker compose up

With Node.js 22.18 or later

git clone {{repository}}.git
cd cratool-tara-oss
npm install
npm start

Then open http://localhost:8787. There is nothing else to set up.

What it is not

Not a compliance guarantee
The tool keeps an assessment complete, consistent and traceable. Whether it is right is still a matter for people who know the product.
Not a service with accounts
It has no sign-in of its own. It is for your machine, or for a team's server behind the sign-in your organisation already has. What that means
Not a copy of a standard
It contains no text of ISO/SAE 21434. The scoring method that comes with it is built from sources that are free to reuse, and names them.
